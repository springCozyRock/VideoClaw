# 一致性手册（对齐当前适配器真实能力）

## 能力边界（先读）

- video-gen 只暴露文本 prompt 与 --reference-image（≤10 张；JPEG/PNG/BMP/WEBP；单张 ≤20MB；边长 240–8000px；**禁止透明通道**）。
- 视频参考与音频参考输入不可用：任何步骤、命令、计划中都不得出现向 video-gen 传视频/音频文件的做法。
- 对白、BGM、音效由 wan3.0-video 随视频一体生成；控制音频的唯一手段是 prompt 文本。
- 相同 seed 不保证逐像素一致。一致性的主要手段是"同一参考图 + 逐字复用的 canonical 文字块"，seed 只是辅助复现手段。
- 参考图约束身份与风格，但不严格锁定首尾帧；衔接预期要按"近似连续"管理，用检查 gate 兜底。

## 全局视觉风格一致

- 规划期确定 global_style_block：风格流派、色调、质感（如动画/实拍质感）、年代与环境基调、光线倾向、镜头语言倾向。
- 该块逐字置于每段 prompt 开头；每段均为 16:9、720P 输出，prompt 中不要求其他画幅。
- 剧情需要局部变化（如昼夜、天气）时，在段内场景描述中声明，global_style_block 本身不改写。

## 人物一致性

1. 每个重复出现的人物一套 canonical 参考图：优先纯色（白）底多视图或全身像 + 特写；一经采用即冻结，全片不换文件。
2. appearance_text canonical 块用固定措辞覆盖：五官、发型发色、服装（含配饰）、体型、标志性特征；出现在该人物的所有段 prompt 中逐字复用。
3. 每段传参考图时，同一人物使用同一文件、同一"图N"位置（推荐全片统一：图1=主角，图2=次要角色，依此类推，衔接帧排最后）。
4. prompt 中用角色名指代，并声明"外观与图N完全一致"；新人物首次出场必须带身份参考图。
5. 剧情内外观变化（换装、时间跨度等）视为新造型：在 plan.json 中登记新的参考图与新的 canonical 块，声明适用段范围；变化点安排在段边界，不在段中途突变。
6. 群众/背景人物不做身份约束，但 global_style_block 保证其画风统一。

## 场景与道具一致性

- 重复场景做无人物定场参考图 + scene canonical 描述；每次回到该场景传同一参考图并用同一"图N"约定。
- 关键剧情道具（会被特写或反复出现）做纯色底参考图并配 canonical 描述；一次性道具只用文字描述。
- 同场景内时间连续的相邻段，可叠加衔接帧参考；跨时间的同场景（如白天/夜晚）只传场景参考图并在 prompt 中声明光线变化。

## 镜头衔接（视频参考不可用时的替代方案）

- 需要画面接续的情形：长单镜头拆段、连续动作跨段、同机位对话正反打的承接。做法：
  1. extract-video-frame 提取前段尾帧（动作段可另取动作高点关键帧）；
  2. 下一段参考图组合 = 身份参考图（人物+场景）+ 衔接帧（排在最后）；
  3. prompt 声明"画面从图N（前段结尾帧）无缝接续，机位与光线保持连续"。
- 禁止只用尾帧做唯一参考：尾帧信息量有限，会漂移身份与风格。
- 衔接帧若有压缩噪点、模糊或风格偏移，检查时按 qa_checklist 处理；重生成时优先强化身份参考与文字描述，必要时放弃该衔接帧改为"同场景重新起幅"并在 continuity.notes 说明。
- 段内多镜头（Shot cut）优先于跨段切镜：能在一段内完成的镜头切换不要拆到两段，减少衔接风险。

## 音频一致性（音色、台词、BGM、旁白）

音频参考输入不可用，必须严格执行：

1. 规划期在 plan.json 的 assets.audio 建立 canonical 文字块：
   - 每个说话人一个音色块：性别、大致年龄、音质（沙哑/清亮/低沉等）、语速、情绪基调、语言与口音；
   - 全片一个 BGM 块：风格、乐器编制、节奏、情绪；剧情要求音乐转场时分段落块并登记适用段；
   - 有旁白时建旁白风格块（讲述人音色 + 语气）。
2. 每段 prompt 中台词格式固定为：`<角色名>（<音色块逐字>）用<语言>说：“<台词逐字>”`；旁白同理。台词在 plan.json 登记后逐字使用，生成时不临场改写；用户给定台词/旁白逐字采用。
3. 用户提供的音频资料：audio-understanding 转写并归纳音色/风格 → 固化为对应文字块，在 user_assets 登记来源与用途；音频文件本身绝不送入 video-gen。
4. 无对白段也要声明 BGM 与环境声状态（延续/渐弱/只有环境声），避免段间音乐忽有忽无。
5. 每段生成后用 audio-understanding 校验四项：台词逐字正确、语言正确、说话人音色符合块描述、BGM 风格符合块描述；漂移即按 qa_checklist 重生成，并在重生成 prompt 中把对应文字块前置、加强调。
6. 段间 BGM 连续性 = 各段使用同一 BGM 块文字；转场只在计划登记的段落边界声明（"音乐由X过渡为Y"）。
7. 口型/演唱/节拍对齐类音画同步需求：把同步要求写进同一段的 prompt（模型随视频一体生成音频），不要指望后期对齐；本适配器没有独立音频生成与替换工具，不要规划"先生成无声画面再配音"的路线。

## 用户资料转化矩阵

| 资料类型 | 检查手段 | 转化方式 |
|---|---|---|
| 人物/场景/物体图片 | get-image-metadata（尺寸/格式/透明通道）+ vision-understanding（内容） | 符合硬约束 → 直接作身份参考图；含透明通道 → 先平铺纯色背景（如 ffmpeg 白底转 JPEG），不可行则 image-gen 以其为编辑参考重绘；分辨率超界 → image-gen 重绘等效图 |
| 语音/歌声/音乐音频 | audio-understanding（转写 + 音色/风格描述） | 固化为音色块/BGM 块/台词文本；文件不进入 video-gen |
| 视频 | vision-understanding（内容/风格，必要时 --with-audio）+ extract-video-frame（关键帧） | 关键帧作图片参考；风格归纳进 global_style_block；音轨信息转文字块 |
| 剧本/小说/设定文本 | 直接阅读 | 剧情扩写依据；台词/旁白逐字入 plan.json；人物与场景设定入 assets |

转化后一律在 plan.json 的 user_assets.processed_into 登记指向；未使用的资料要写明原因（如"与需求冲突，以文字需求为准"）。

## Seed 策略

- 每段固定 seed 写入 plan.json；重生成第 1 次保持 seed、只改 prompt/参考图；第 2 次可换 seed。每次 attempt 的 seed 与改动点记入 qa.attempts。
- image-gen 参考图登记生成 seed；需要重绘同款时先尝试原 seed + 微调 prompt。
- 不把"换 seed 多抽几次碰运气"当作主要手段：优先修 canonical 块与参考图组合，控制付费调用次数。
