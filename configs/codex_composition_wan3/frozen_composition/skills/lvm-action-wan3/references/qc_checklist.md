# QC 与重生成规则（动作与追逐长视频）

用于 Step 5 段级检查与 Step 7 全片检查。所有检查都是制作辅助（抽样理解），不是论文正式评测协议；结论必须用“实际看到/听到什么”的观察描述记录，不要把抽样理解当成逐帧检测，也不要编造未执行的检查。

## 检查工具与调用形态

统一用 video-gen/image-gen/merge-video 同一个适配器入口（命令与解释器路径见各基础技能 SKILL.md）：

- 视觉：`understand --image {绝对路径} --prompt "{问题}"`
- 视频（可含音）：`understand --video {绝对路径} --prompt "{问题}"`，需要音画一起看时加 `--with-audio`
- 音频：`understand --audio {绝对路径} --prompt "{问题}"`
- 元数据：`probe --input {绝对路径}`
- 取帧：`extract --input {绝对路径} --seconds {秒} --output frames/{名称}.jpg`
- 网格图：grid-generate 技能目录下的 `scripts/grid_generate.py`，参数见该技能 SKILL.md
- 合成清单校验：本技能 `scripts/validate_manifest.py`

限制必须记住：视频最多抽 16 帧，音频检查最多前 120 秒。超过 120 秒的成片，音频一致性检查改为对各片段分别执行后汇总。

## 段级 QC 流程

每段生成后立刻执行，不要攒到最后：

1. `probe` 核对：实际时长（秒）、1280x720、30fps（或适配器返回的真实值）、音频流存在。
2. `extract` 取末帧（`--seconds` 取接近实际时长末尾，例如实际 8 秒取 7.8）与 1–2 个关键中间帧，路径写回 plan.json 的 handoff_out。
3. `understand --video` 做视觉检查（模板见下）。
4. `understand --video ... --with-audio` 做音频检查（模板见下）。
5. 把参考图与末帧一起给 `understand --image` 做身份比对（可选，漂移风险高的角色段必做）。
6. 写判定 PASS / REGEN / ACCEPT_WITH_NOTE 到 plan.json 与 observations.md。
7. REGEN：改动至少一处（prompt 措辞、参考图、seed）后重新提交，最多 2 次；每次改动都是新的付费提交。

## 段级检查 prompt 模板

视觉（`understand --video`）：

```
这是一段动作/追逐视频片段，本段预期内容是：{plan.json 的 description}。请按编号回答，只描述实际看到的画面：
1) 画面中出现几个人物，逐个描述外观（性别、年龄段、发型发色、服装颜色与款式、体型、随身道具）与正在做的动作、朝画面哪一侧移动；
2) 与预期内容的差异：哪些动作没有发生、发生顺序是否不同；
3) 物理与连续性异常：肢体数量与关节方向、穿模、瞬移、突然加速或减速、物体或人物凭空出现或消失、载具轮子转动方向与行进是否一致、背景位移与速度是否匹配；
4) 镜头类型与运动：实际是什么机位、焦段感受、镜头如何运动，与要求的 {shot_mode 与镜头描述} 是否一致；
5) 环境：地点、时间、天气、光源方向、主色调、已被破坏或改变的物件状态；
6) 画面中是否出现可读文字、字幕、水印、logo 或多余路人；
7) 最后一帧：主体姿态、在画面中的位置、移动方向、速度感、与其他人物或目标的距离（用于接续下一段）。
```

音频（`understand --video ... --with-audio`）：

```
请听这段视频的音轨并按编号回答，只描述实际听到的内容：
1) 逐句转写听到的台词，并标注每句说话人的性别与大致年龄；
2) 描述每个说话人的音色：音高、音质（沙哑/清亮/低沉等）、语速、口音、情绪；
3) 背景音乐：乐器编制、节奏快慢、风格、情绪，是否贯穿整段，是否在某个时间点中断或突变；
4) 音效清单：脚步、引擎、轮胎摩擦、风声、撞击、玻璃、喘息、衣物摩擦、人群、环境底噪等，实际听到哪些；
5) 是否存在静音区间、爆音、异常噪声或音画明显不同步；
6) 台词与画面中人物的口型或动作是否大致对应。
```

身份比对（`understand --image`，传角色参考图或末帧）：

```
对比这两张图：第一张是角色参考图，第二张是视频片段中的帧。请指出在脸型、发型发色、肤色、体型、服装颜色与款式、鞋、随身道具、标志性特征上的每一项差异，并说明差异是否严重到会被观众认成另一个人。
```

## 全片 QC 流程

1. `probe final.mp4`：分辨率 1280x720、30fps、音轨存在、时长等于目标总时长。
2. grid-generate `by-time`（间隔按目标时长选，例如 60 秒用 `--interval 2 --cols 6`）生成全片概览网格图，再用 `understand --image` 做整体检查（模板见下）。
3. grid-generate `by-shot`（`--frame first`，必要时再跑一次 `--frame last`）生成镜头网格，检查跨镜头身份、服装、场景、方向漂移与镜头语言执行度。
4. `understand --video final.mp4 --with-audio`：剧情逻辑与因果连贯、动作是否完成、音画一致（超过抽帧或 120 秒限制时改为分段检查后汇总）。
5. `understand --audio` 或对片段逐个执行音频检查：同一说话人音色是否一致、BGM 是否风格一致且贯穿、音效层次是否到位。
6. 与 merge 生成的 final.manifest.json 比对：片段顺序、路径、时长是否与实际一致。
7. 结论写入 observations.md，并把 final_checks 记入 plan.json。

## 全片检查 prompt 模板

网格图整体检查（`understand --image`，传 by-time 网格图）：

```
这是同一条动作/追逐视频按时间顺序抽帧拼成的网格图，每格左上角有序号、左下角有时间戳。请按编号回答：
1) 按序号复述剧情推进：每一格发生了什么，动作与追逐的因果链是否成立，哪里出现逻辑断裂；
2) 主角与对手的外观在各格之间是否一致：逐项列出脸、发型、服装颜色、体型、随身道具的变化，并给出对应格号；
3) 追逐方向是否一致：主体在各格中朝画面哪一侧移动，哪一格出现方向反转；
4) 场景与光线是否连续：地点、时间、天气、色调有无突变，环境破坏状态是否延续；
5) 人数与物件守恒：哪一格多出或缺少人物、物件凭空出现或消失；
6) 物理异常：肢体、穿模、瞬移、载具运动、碎屑与重力；
7) 节奏：哪些格之间动作重复或停滞，哪些地方切换过于突兀；
8) 画面中是否出现可读文字、字幕、水印。
引用问题时请给出格号和时间戳。
```

镜头网格检查（`understand --image`，传 by-shot 网格图）：

```
这是按镜头边界抽帧拼成的网格图，每格代表一个镜头。请回答：
1) 一共有多少个镜头，每个镜头的机位类型与镜头运动是什么；
2) 相邻镜头之间是否存在身份、服装、场景、方向或光线的跳变，指出格号；
3) 镜头语言是否服务于动作节奏：高强度段落是否用了短镜头与运动镜头，铺垫段落是否用了稳定长镜头；
4) 是否有镜头内容重复、无信息量或与前后镜头无因果关系。
```

全片音画检查（`understand --video final.mp4 --with-audio`）：

```
请按编号回答，只描述实际听到和看到的内容：
1) 全片剧情概要（按时间顺序），指出逻辑不连贯或因果缺失的地方及大致时间点；
2) 所有台词逐句转写，标注说话人；同一说话人在不同时间点的音色是否一致，哪里出现音色变化；
3) 背景音乐：风格与乐器是否全片一致，是否在片段接缝处出现明显断裂、风格跳变或静默，给出大致时间点；
4) 音效：动作与追逐应有的脚步、引擎、撞击、风声、喘息等是否出现，哪些动作缺少对应音效；
5) 音画同步：哪些地方声音与画面动作明显不匹配；
6) 整体观感上最影响可信度的三个问题。
```

## 判定标准与重生成预算

| 判定 | 触发条件 | 处理 |
| --- | --- | --- |
| PASS | 身份无漂移、方向正确、动作按预期完成、无严重物理异常、音频有台词/BGM/音效且符合要求 | 标记 adopted，进入下一段 |
| REGEN | 角色身份明显错误或换人、主体未执行关键动作、追逐方向反转、严重穿模或多肢体、人数错误、静音或台词完全缺失、场景与设定不符 | 改动至少一处后重生成，每段最多 2 次 |
| ACCEPT_WITH_NOTE | 轻微抖动、背景细节差异、次要道具变化、BGM 在接缝处可感知的轻微断裂、慢动作轻微形变 | 记入 observations.md 的已知问题，不重生成 |

预算与成本纪律：

- 每段重生成上限 2 次；全片重生成段数不超过计划段数的三分之一，除非用户明确要求更高完成度。
- 重生成必须真实改动（prompt 措辞、参考图或 seed），否则适配器会复用同一任务，等于没有重生成，也不会得到新画面。
- 达到上限仍不达标：采用最不坏的版本，把缺陷写进 observations.md 与 plan.json 的 observations 字段，继续推进，不要无限重试烧钱。
- 付费提交返回 SUBMISSION_UNKNOWN 或失败：立即停止，不重复提交，保留现场，记录状态并向用户说明。
- 修完问题段后必须重新 merge 并重新做全片 QC 与 manifest 导出，不能只改清单不改视频。
