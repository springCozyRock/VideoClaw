# lvm-educational-wan3：科普/流程讲解长视频制作工作流

按本文件顺序执行；细节按需读取 references/：

- 分段提示词写法、旁白/音乐的文字控制模式：`references/segment_prompts.md`
- 一致性资产清单、QA 检查表、失败处理策略：`references/consistency_qa.md`

## 硬性约束（当前适配器真实能力，必须遵守）

1. 视频生成固定 `video-gen`（wan3.0-video）：720P、16:9、自带音频、关闭服务端提示词扩写；单段时长为 2–30 的整数秒。
2. `video-gen` 只接受文本提示词与参考图（`--reference-image`，最多 10 张，可重复；JPEG/PNG/BMP/WEBP、单张≤20MB、边长 240–8000 像素、不能含透明通道）。**参考视频、参考音频未开放**：用户提供的音频/视频只能先转化为文字描述或帧图像再进入生成链路。
3. 音频随视频一次生成，无法后期配音/替换：旁白台词、音色、背景音乐只能写进每段提示词，用**逐字复用的固定描述文本**保持一致（见 `references/segment_prompts.md` 的"声音锚点"）。
4. `merge-video` 只接受真实生成、含音轨的片段，按 `--input` 顺序拼接，可用 `--duration` 裁掉多余尾部；禁止拉伸、循环、冻结画面或补黑凑时长。
5. 相同任务名+提示词+参数+参考内容会复用历史任务；已失败或 SUBMISSION_UNKNOWN 的任务会停止且不重复收费提交。重试必须改变任务名/提示词/seed 之一，SUBMISSION_UNKNOWN 时保留现场并停止该次提交。
6. 全流程在当前会话内**顺序执行**：不使用 sessions_spawn、并行子代理或其他 agent 委派；单段生成默认同步轮询到下载校验完成（`video-gen` 自带轮询），需要中断时用 `--background` 并重复同一命令续接。
7. 所有产物写入 `get-output-dir` 返回的任务目录，不手动另建目录树；`plan.json`、资产清单、检查记录一律保存在该目录中留档。

## 工作流

### 第 0 步：读取输入与参考资料

1. 解析任务输入：文字需求（主题、受众、必须讲清的知识点/流程步骤）、目标总时长、音画约束（语言、旁白风格、音乐风格、画幅等）。
2. 逐项处理用户提供的参考资料并记录到资产清单：
   - 图片：`get-image-metadata` 查格式/边长/透明通道，`vision-understanding` 描述内容；不满足参考图硬性要求时先转换（去 alpha、缩放到边长 240–8000、转 JPEG/PNG）。
   - 视频：`get-video-metadata` 查元数据，`vision-understanding`（可加 `--with-audio`）理解内容，`extract-video-frame` 抽取关键帧作为候选参考图。
   - 音频：`audio-understanding` 转写台词/描述音色与背景声，把结果写成"声音锚点"文本。
   - 文本：直接通读，必要时扩写、消歧、补充细节。
3. 参考资料缺什么就自己补什么：缺失的角色/场景/图表参考图用 `image-gen` 生成。

### 第 1 步：初始化输出目录与任务追踪

1. 调用 `get-output-dir` 取得任务目录（后续所有相对路径以此为根）。
2. （可选）用 `task-tracker` 以本 SKILL.md 初始化任务栈，每完成一步 `next-step` 记录输出与文件路径。

### 第 2 步：内容规划，写出 plan.json

不预设固定故事，按当前输入自主规划：

1. 把讲解内容组织成叙事结构：开场引入 → 分节讲解（知识点/流程步骤，按逻辑依赖排序）→ 总结收尾；总时长分摊到各节。
2. 写完整旁白/讲解词（含必要的角色台词），信息不足时自行补全细节，确保覆盖需求中的全部要点且逻辑连贯。
3. 切分片段：每段是一个逻辑完整的讲解单元，时长 2–30 秒整数（建议 8–15 秒），所有片段时长之和 ≥ 目标总时长（`merge-video --duration` 可裁尾，不能补长）。
4. 为每段确定：画面内容（场景、主体、动作、图表/文字元素）、镜头（默认单镜头一段；确有需要才用 "Shot cut" 多镜头，见 `references/segment_prompts.md`）、本段旁白文本、要引用的资产 id 列表、seed。
5. 抽出全片一致性资产：角色（外观+声音）、场景、关键物体/图表、视觉风格、旁白音色与背景音乐描述；每项给出资产 id、来源（用户提供/生成）、用途。
6. 保存 `plan.json` 到任务目录（结构见 `references/consistency_qa.md`），此后每完成一段就回写实际结果（task_id、文件、检查结论、改动）。

### 第 3 步：构建一致性资产

1. 角色：用 `image-gen` 生成单张多视图设定图（同一张图内三视图、纯色背景、不含透明通道），或采用用户提供的合格图片。
2. 场景：每个反复出现的场景生成一张关键参考图，锁定布局、光线、配色。
3. 物体/图表/流程示意：讲解中反复出现的装置、界面、流程图各生成一张参考图。
4. 全片视觉风格与"声音锚点"（旁白音色、语速、语气、BGM 风格与强度的固定描述文本）写成文本资产，逐段原样引用。
5. 所有资产登记进 `plan.json` 的 assets 清单：id、绝对路径或文本内容、被哪些片段引用。只为需要的资产生成参考图，不必每段都生成。

### 第 4 步：按顺序逐段生成视频

按 plan.json 顺序串行执行，每段：

1. 组装提示词：套用 `references/segment_prompts.md` 的模板 = 风格锚点 + 场景/主体描述 + 本段画面动作 + 镜头语言 + 声音锚点 + 本段旁白；引用参考图时在提示词中用"图1/图2…"显式说明每张图约束什么（如"图1为讲师形象，保持五官发型着装一致"）。
2. 调用 `video-gen`：`--reference-image` 按提示词中图1、图2的顺序传入（≤10张），`--duration` 为整数秒，`--seed` 用计划值并记录。输出为任务目录内相对路径。
3. 段内自检（生成完立即做）：
   - `get-video-metadata`：时长、分辨率、帧率、音轨存在。
   - `vision-understanding`：画面内容、角色/场景与参考图是否一致、文字图表是否可读、有无肢体/物理异常。
   - `audio-understanding`：旁白是否念了计划台词、音色与 BGM 是否符合声音锚点。
4. 不合格处理：按 `references/consistency_qa.md` 的失败策略改提示词/seed/参考图后重新生成（新任务名）；合格则登记文件路径。
5. 需要跨段延续画面时，用 `extract-video-frame` 从本段取帧，`vision-understanding` 确认质量后作为后续段的补充参考图；不要只依赖尾帧接续，始终以设定图资产为主、帧图为辅。

### 第 5 步：合成 final.mp4

1. 所有片段合格后，按叙事顺序把各段绝对路径依次传给 `merge-video --input ... --output final.mp4 --duration <目标总秒数>`。
2. 合成后 `get-video-metadata` 核对总时长、720P/16:9/30FPS、音轨完整。

### 第 6 步：成片质检与修复

1. `grid-generate` 生成全片网格总览图，连同 `vision-understanding`（对 final.mp4，必要时 `--with-audio`）检查：叙事逻辑连贯、章节顺序正确、角色/场景/配色全片一致。
2. `audio-understanding` 检查旁白清晰度与全片音色/BGM 一致性（单次音频检查最多前 120 秒，长片分段抽查）。
3. 对照 `references/consistency_qa.md` 的成片检查表逐项记录结论到 `qa_report.md`；发现问题的片段回到第 4 步重生成，再重新合成与复检。

### 第 7 步：交付与留档

确认任务目录中保留：`final.mp4`、`plan.json`（含每段实际生成记录与 seed）、资产清单（参考图与文本锚点）、各段视频、`qa_report.md` 与检查记录。向用户报告成片路径、总时长、结构概要及已知限制。

## 常见错误（务必避免）

- 把用户音频/视频直接当 `video-gen` 参考传入（未开放）；必须先转成文字锚点或帧图像。
- 只靠上一段尾帧维持一致性；必须以设定图资产为主参考。
- 每段旁白/音色/BGM 描述各写各的；必须逐字复用声音锚点文本。
- 片段时长之和小目标总时长后又想靠 merge 补长；规划时就要留足余量。
- 手动 mkdir 建输出目录；一律使用 `get-output-dir`。
- 失败任务原样重提导致复用失败结果或重复收费；重试必须改任务名/提示词/seed，SUBMISSION_UNKNOWN 立即停止并保留现场。
- 委派子代理或并行生成；本工作流在当前会话串行完成。
