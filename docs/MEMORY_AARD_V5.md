# V5：先规划角色形态，再用实际视频验证状态

## 当前流程

1. 从原始 VideoClaw 剧本、分镜及人物锚点中提取初始外观和有原文依据的变化。程序延续未改变属性，合并相同形态，生成每段的开始/结束绑定。人物简介不会单独触发变身，返回日常也不会自动恢复已移除衣物。
2. 原始身份锚点由程序保留。环境/物件按依赖 DAG 生成并核验风格。角色先获得经过核验的单一初始形态，再由这个父参考派生其他形态；原始设定图继续用于独立身份/风格核验，避免混合形态设定图污染生成。
3. 角色参考分别检查明确属性、身份和风格。服装移除不能仅由新服装出现来推断；必要时生成敞开外衣、露出腰腹的可观察参考。身份/风格失败或关键衣物被遮挡时重新生成，避免持续沿用错误候选。
4. 当前段与下一段分别检索参考和历史；可使用非相邻历史视频的具体镜头末帧。按片段开始/结束绑定优先使用对应形态图，选择外推或首尾帧插值。
5. 实际首帧、末帧、视频分别观察。预期状态与实际观察分开保存。角色是否可见、属性是否可判断分开表示：明确不存在是 observed=false，遮挡是 unknown，实体在画外才是 not_visible。
6. 视频中显式记录 visible/offscreen/uncertain 时间段，验证全部可见窗口。合法特写切换不要求另一个角色在画外仍有身份证据；缺失剧情和角色错配由主视频评审处理。不能编造跨越画外时段的观察证据。结构有效但证据覆盖不足时保留原始观察，将对应事实记为 unknown，交由质量门控和既有候选预算处理；不再因此中断整个流程。时间线结构错误仍作为错误处理。
7. HITS 区分 Edit 与 Regenerate；后者由 MAPO 构建新提示，不要求无意义的 Edit 提示词。MAPO 使用语义向量和带真实媒体来源的正负经验。关键状态在固定候选预算内仍不明确或错误时阻断，不把最佳候选冒充通过。

VideoClaw 在 VIDEO_GENERATION 阶段安装 memory 的控制器和后端，原始剧本/分镜仍由宿主提供。核心协议与 VideoClaw 适配层分离，目前真实集成验证仅覆盖 VideoClaw。视频 API 接收提示词、首帧和可选末帧；整个记忆库并没有直接输入视频模型，额外参考主要作用于边界图像生成、规划和评审。

旧 V1/V3 导入和运行入口保留。新实验通过 `scripts/run_memory_aard_v5_snapshot.py` 或共享队列运行器加载独立源码快照。

## 复用与实验留痕

每个运行保存输入、源码哈希、调用回执、全部候选、原始评审、状态检查和选中视频。未知外部调用结果不自动重复提交。

恢复已完成参考时，必须验证源检查点、原始锚点与媒体哈希、完整形态定义一致，并用当前谓词重新检查旧的实际观察。复用操作单独记账；旧失败不会改写成成功。恢复视频评审可沿用已经生成的同一视频，不必重新生成。

## 与 AARD 的关系

全局形态参考、依赖图、MVMem、独立下一段检索、外推/插值、HITS 和语义 MAPO 对齐论文主要机制。显式属性契约、原文引用校验、时间段覆盖和关键状态门控属于本项目的工程扩展，不能称为论文逐项等价复现。候选预算、模型、窗口及初始化细节仍与论文实验不同。

规划、视觉识别和评审仍依赖模型。复杂服装遮挡、多角色身份、画风和细粒度运动都可能出错。可插拔记忆提供约束和证据闭环，不能保证底层生成模型一定实现目标。

## 本轮验证

Native 环境相关检查：100 项通过，0 跳过；正式 memory Python 文件按哈希与测试快照核对。

- DirectorBench narrative_074：5 段/60 秒，关注围裙移除、赛博风衣、仅一次变身、战后状态及巨猫缩小。
- MSVBench story08：9 段/60 秒，关注跨场景身份、服饰、画风和剧情推进。
- MSVBench story01：8 段/47 秒，关注大小兔身份/比例、睡前故事顺序及结尾。

使用相同原始输入和锚点，不复用旧运行中的人工改写计划。每轮参考图、边界图和视频固定最多 3 候选，关键状态门控保持启用；原始失败和不同修订均保存。按用户要求，共享 Qwen 队列的请求间隔改为 5 秒；明确限流后的重试等待统一为固定 5 秒。新进程使用此策略，已运行的冻结任务仍使用启动时加载的旧代码。配置及模拟验证见 experiments/rate_limit_5s_20261031/deployment.json。

这些案例也被用于定位和修复实现问题，因此属于开发回归，且实际运行采用不同的冻结小修订，不是未见测试集或同一固定版本上的严格对照实验。内部评审分数不是官方基准。实际进度与结果见 `experiments/memory_aard_v5_validation_20261031/report.json` 和 `REPORT.md`；离线检查通过不等于视频质量提升。
